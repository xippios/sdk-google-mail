# Upstream documentation snapshot — Gmail

Source of truth for every endpoint wrapper (ADR-0003). The files in this directory are
written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the pages in the
table below and refreshed deliberately by PR, so that changes show up as diffs. This
file is generated by the same script; nothing here is edited by hand.

## How this is captured

The discovery document is kept with its keys sorted: the discovery service serves the
members of every object in a new order on each request, so the script checks that the
fetched text is the document written with `json.dumps(indent=2, ensure_ascii=False)` in
its served order and writes it again with `sort_keys=True`; nothing else changes, and
arrays keep their order. The REST reference at
https://developers.google.com/workspace/gmail/api/reference/rest names the document,
which it calls a machine-readable specification of the API; the script keeps the
document and not the reference's pages. Each HTML page is converted to Markdown with
markdownify 1.2.3 (Beautiful Soup 4.15.0, html.parser), headings in ATX style and
underscores left unescaped, so that names read as upstream writes them, links and images
made absolute. A developers.google.com page keeps its title, its `devsite-article-body`
and its content footer, with the licence and the Last updated date; the Gmail Help
article keeps its title and its article text (`div.cc`). Left out: the site's
navigation, breadcrumbs and footers, the feedback and rating widgets, the Page Summary
panel of the OAuth 2.0 pages, which they mark "Generated with AI", icons and buttons. A
callout (`aside`) becomes a blockquote. A table with merged cells (`rowspan`, `colspan`)
or a nested table stays HTML, with its cells' spans, links and inline markup and no
other attribute, and its row's note counts them (conventions §3). Every page's body
changes on each request, the HTML pages by a script nonce and the order of attributes in
their navigation, so every row records no size, sha256 or validators: the files are what
a refresh diffs.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Bytes and sha256 are those of the body as fetched: a converted page's row
holds the HTML page's, an excerpt's the whole document's. Last-Modified is the HTTP
header in UTC, ETag as sent. A page recorded without a file is `(no file)`, and a body
that changes on every request records no size, sha256 or validators. Requests go one at
a time, 2 s apart, each retried at most once, identified as `xippios-google-mail
refresh_upstream (+https://github.com/xippios)`; no API key is sent or read.
